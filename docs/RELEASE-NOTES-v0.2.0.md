# v0.2.0 — 修复主角与部分NPC在修改器中丢失的问题 + 颜色范围防呆

依据 2026-10-03 真机诊断包（`yaowanggu-diag-20261003-092116.zip`）实证分析定位并完成修复。

## 问题定位与修复

1. **主角（ID 1）丢失修复**：
   - **根因**：用户在五官界面将发色明暗调整至 440，由于原 `PersonFinder` 中发色明暗上限硬编码为 400，导致角色窗口在校验时判定越界失败，未被加入角色列表；
   - **修复**：`PersonFinder` 增加合理容错范围（部件 0..30、颜色 0..1000），成功恢复识别主角 ID 1（全档 362 条角色记录实现 100% 识别与锚定）。

2. **27 位 NPC 识别丢失修复**：
   - **前发超限（26 位 NPC）**：原生 NPC 记录中前发取值包含 13、14（如 ID 8、15、17、62 等），原校验上限 12 导致拒识。现将 `FaceSchema` 前发上限提升至 16，`PersonFinder` 放宽至 30。
   - **双色相 0 误判（1 位 NPC）**：原生 NPC #332（ID 333）为纯黑发/红瞳（发色色相与瞳色色相均为 0），原代码将其当作退化窗口剔除。现移除该不合理限制。

3. **五官与颜色编辑防呆**：
   - `FaceScreen` 颜色项 `+10` / `−10` 增加 `coerceAtMost` / `coerceAtLeast` 钳制保护（色相 0..360，饱和/明暗 0..400），防止再次调出越界数值。
   - `TrainerViewModel.stageFaceEdit` 增加统一输入钳制 `value.coerceIn(0L, maxVal)`。

## 发布变动
- CI / GitHub Actions 调整：正式 Release 仅发布经过签名校验的 `yaowanggu-trainer-v0.2.0-release-signed.apk`，精简发布包体积与下载体验。
